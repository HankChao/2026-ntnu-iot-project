# clothes_predict — 衣物乾燥進度與時間預測（Python 實驗）

用 `data/*.csv` 的衣夾原始資料（可用環境變數 `CLOTHES_DATA_DIR` 指到別的資料夾），測試「目前乾燥進度」、「過去＋未來的乾燥曲線」、「預測乾燥時間」的方法。
驗證完之後要移到 `iot_server/app`（Bun + Hono）。

```bash
cd clothes_predict
uv sync
uv run python scripts/plot_raw.py            # 1. 每個 CSV 的原始折線圖 → out/raw_*.png
uv run python scripts/plot_sessions.py       # 2. 5 段晾衣的重量/ADS/touch 正規化疊圖 → out/sessions_overview.png
uv run python scripts/predict_kalman.py      # 3. 方法 A：EKF（--model exp、--wind=gain|off、--ads=off、--prior=all）
uv run python scripts/predict_curve_fit.py   # 4. 方法 B：曲線擬合（--model exp、--no-prior）
uv run python scripts/predict_history_mean.py  # 5. 方法 C：歷史平均（iot_server 現行做法，基準）
uv run python scripts/compare_methods.py     # 6. 全部方法的比較表與圖 → out/compare_methods.png
uv run python scripts/detect_sessions.py     # 7. 自動偵測開始晾／收下，和人工標記比對
```

每個 script 都可以單獨跑。共用的程式在 `src/clothes_predict/`：
- `data.py`：讀 CSV、晾衣區段定義 `SESSIONS`（含衣物名稱、有沒有開風扇）、濾掉 HX711 讀值失敗，並取 1 分鐘中位數（模擬正式環境每分鐘一筆）＋ `wind` 指標
- `models.py`：乾燥曲線模型（純函式，可以照抄成 TypeScript）
- `evaluate.py`：線上回放，模擬每分鐘收到一筆、每 10 分鐘問一次預測，並畫圖、印誤差

| 場次 | 衣物 | 時長 | 失水量 (counts) | 重量 95% | ADS 到頂 | 備註 |
|---|---|---|---|---|---|---|
| S1_1114 | 抹布 | 13.6h | 26,037 | 11.8h | 10.2h | 沒有溫濕度 |
| S2_1115 | 運動長褲 | 11.2h | 23,650 | 5.9h | 4.0h | `0101-0811` 是這份的前半段，只用 `0101-1225` |
| S3_1117a | 抹布 | 17.2h | 29,312 | 12.7h | 12.4h | 18:50 使用者先拆下 ADS 電阻夾（抹布還掛著），以此為結束、標為差不多乾 |
| S4_1117b | 抹布 | 8.7h | 24,506 | 4.9h | 5.2h | **有開電風扇**：21:40–22:02、00:30–02:00 |
| S5_1119 | 短褲 | 3.8h | 17,792 | 3.0h | 2.5h | ADS 雜訊很大 |

- **重量（hx711）**：先近乎**直線**下降（等速乾燥期），最後一段很快收平（減速期），不是單純指數衰減。
- 偶爾會掉到 0：是讀取失敗，已過濾（< 50,000）。
- 會有**向下的跳階**（可能是滴水）。
- **溫度漂移**：S4 在 02:00–03:30 重量回升 2.3k，同時氣溫從 29.1°C 降到 28.1°C，大約 −2k counts/°C，約占總失水量的 10%。
- **電風扇**：
  - 速率變成約 4–6 倍：平常約 1.8k/h，有風時 7k–11k/h。
  - 每分鐘重量讀值的 IQR 從 ~150 跳到 1,100–2,200，很好分辨（`load_session` 的 `wind` 欄位，門檻 800）。
  - ⚠️ 這裡是 1 Hz 原始資料，每分鐘約 60 筆。正式環境 ESP32 只傳 10 次讀值的中位數，要用這個指標，**韌體得多傳一個 IQR 或 max−min**（`validation.ts` 也要放行這個欄位）。10 次讀值只涵蓋約 1 秒，偵測效果要實測才知道。
- **ADS1115**：
  - 濕的時候低，乾了以後回到 ~25.7k 的上限。
  - 到頂時的重量進度：抹布 0.88／0.89／1.03（有風）、長褲 0.84、短褲 0.91，可以當「快乾了」的觀測。
  - 前段的變化各場不一致，不適合拿來算進度。
- **touch**：乾燥過程中慢慢下降，收平的時間比重量晚。

## 定義

- 重量 W = 乾重 Wd + 剩下的水 m
- **乾燥進度** = (W0 − W) / (W0 − Wd)
- **乾**：進度 ≥ 95%（`evaluate.DRY_LEVEL`）。評估用的真值以整段資料的最後 30 分鐘當 Wd。
- 線上預測時不知道 Wd，要靠模型估計。這是整個問題的核心：**等速期重量是直線，光看曲線分不出乾重在哪**。

## 乾燥模型（`models.py`）

兩段式（等速 → 減速），一條平滑微分方程：

```
dm/dt = -R · (1 - exp(-m/Mc))
m(t)  = Mc · ln(1 + (exp(m0/Mc) - 1) · exp(-R·t/Mc))        ← 解析解
t(m*) = (Mc/R) · ln((exp(m0/Mc) - 1) / (exp(m*/Mc) - 1))     ← 到乾的時間，解析解
```
R 是等速期的蒸發速率，Mc 是臨界含水量（目前固定為總水量的 20%）。對照組是指數模型 `m = m0·exp(-k t)`。

## 方法 A：EKF（`predict_kalman.py`）

- **狀態** `[m, log R, Wd]`，量測 `W = Wd + m`；速率取 log 保證為正。Jacobian 用數值微分，TypeScript 版也照這樣寫。
- **先驗**：失水量 ~ N(μ, σ)。
  - 有同一件衣物的紀錄：用那幾場的平均，σ ≥ 10%。
  - 沒有紀錄：用全部場次的平均，σ = 40%。
  - 這裡用留一法模擬「過去的紀錄」，不算訓練。
- 開始時 m 和 Wd 設為完全負相關（m + Wd = 目前讀值）。掛上後前 5 分鐘取中位數初始化，前 10 分鐘的晃動不算風。
- **風**（`--wind inflate|gain|off`）：
  - `inflate`：有風／沒風切換時，把 log R 的變異數加 1，讓速率很快重新收斂；有風時量測雜訊 ×3。
  - `gain`：另外假設有風時 R ×4。
  - 判斷有風／沒風需要連續 3 分鐘。
- **ADS1115 融合**（`--ads on|off`）：ADS 到頂時加一次「進度 = 0.9 ± 0.08」的非線性觀測。
- 創新值超過 25σ 就丟掉，視為有人碰衣夾。
- **輸出**：濾波後的過去曲線、解析解畫的未來曲線、進度、乾燥時間。未來曲線假設目前的風況會持續。

## 方法 B：曲線擬合（`predict_curve_fit.py`）

- 對目前為止的全部資料做加權非線性最小平方（soft_l1、3 小時遺忘），並加上同一個失水量先驗。
- `MEAS_SD` 設 1500，不是 400：殘差有漂移、前後相關，設太小的話幾百筆資料會把先驗完全壓掉。

## 結果（`compare_methods.py`）

ETA 誤差取實際乾燥時間 20%–90% 期間的平均（S3 已改用 18:50 為結束）：

| 方法 | ETA 誤差 | 排除 S4 | 進度誤差 | S4 開風扇後 +15/+30/+60 分（實際 4.90h） |
|---|---|---|---|---|
| **EKF 兩段式＋風＋ADS** | 1.69h | **1.05h** | **0.061** | **5.20 / 5.33 / 5.35** |
| EKF 兩段式＋ADS | 1.44h | 1.05h | 0.061 | 6.40 / 5.71 / 5.78 |
| EKF 兩段式＋風＋ADS（先驗不分衣物） | 1.55h | 1.12h | 0.076 | 5.01 / 4.98 / 5.00 |
| EKF 兩段式 純重量 | 1.63h | 1.27h | 0.072 | 6.40 / 5.71 / 5.78 |
| EKF 指數 純重量 | 5.99h | 5.22h | 0.062 | 9.15 / 6.98 / 6.87 |
| 擬合 兩段式＋先驗 | 1.78h | 1.40h | 0.082 | 9.86 / 9.47 / 9.86 |
| 擬合 兩段式 無先驗 | 14.51h | 15.39h | 0.319 | 55.4 / 49.9 / 44.0 |
| 歷史平均（現行做法） | 3.90h | 3.38h | 0.212 | 12.27（固定） |

- 5 場資料，各 EKF 變體之間的差距不顯著；S4 開風扇前不可能預知，所以另列「開風扇後」的修正速度。
- EKF 約是現行歷史平均做法誤差的 1/3。兩段式模型明顯比指數模型好；不加先驗不能用。
- ADS 融合對沒有歷史的衣物最有用；風的處理讓開風扇後 15 分鐘就修正到接近實際。
- 同衣物先驗沒有明顯比較好：抹布的失水量先驗已經很準，誤差主要來自速率變化（環境、風）。

## 可以加強的方向（不用機器學習）

1. **用溫濕度修正速率**：R ∝ 飽和水氣壓差 VPD(T, RH)，空氣盒子已經有 T、RH。在 EKF 裡把 log R 換成 log(R/VPD)，就能自動反映天氣變化。這是目前誤差最大的來源。
2. **韌體多傳 hx711 的 IQR／max−min**：拿來偵測風。
3. **乾重直接量**：掛濕衣前先把乾衣掛上，按一下「秤乾重」，或在衣物庫存乾重 → Wd 的不確定性降到只剩漂移。對新衣物最有用。
4. **溫度漂移補償**：空夾子時記錄 hx711 對溫度的斜率（S4 估計約 −2k counts/°C）。
5. **touch 收平也可以當第二個「乾了」的觀測**，和 ADS 一樣做法。

## 機器學習方法（只列出，**尚未訓練**）

目前只有 5 場，而且衣物不明，不夠訓練任何模型。下面依「需要的資料量」排序：

| 方法 | 需要的資料 | 作法 | 部署 |
|---|---|---|---|
| **經驗貝氏／階層式先驗** | 每件衣物 2–3 場 | 從歷史紀錄估計每件衣物、每種材質的 loss、R、Mc 分布，直接當 EKF 的先驗。說是「學習」，其實只是統計 | Bun 就可以 |
| **線上遞迴最小平方（RLS）學 VPD／風的係數** | 10+ 場 | 學 R = a·VPD^b·(風 ? g : 1) 的 a、b、g | Bun 就可以 |
| **高斯過程回歸（GP）** | 1 場就能用，越多越好 | 以 EKF 兩段式當平均函數，GP 只學殘差，可以給信賴區間 | Python 容器（scikit-learn / GPyTorch） |
| **梯度提升樹（LightGBM／XGBoost）預測剩餘時間** | 30–50 場以上 | 特徵：經過時間、EKF 的 m／R／進度、近 30 分鐘斜率、ADS／touch 正規化值、wind、T、RH、VPD、材質、款式；目標：剩餘時間。可以用 quantile loss 給上下界 | Python 容器訓練，模型可匯出成 ONNX，或在 TS 做 tree inference |
| **存活分析（Cox／Weibull AFT）** | 30+ 場 | 把「乾了」當事件，可以處理提早收衣（censored）的紀錄 | Python 容器 |
| **序列模型（GRU／TCN／Transformer）** | 數百場 | 直接吃原始序列輸出剩餘時間 | Python 容器，目前不建議 |

建議順序：先把 EKF 兩段式＋衣物歷史先驗＋ADS 融合放進 Bun。累積到 30 場以上、有材質標籤後，再考慮在 Python 容器訓練 LightGBM，把 EKF 的狀態當特徵（混合式）。

## 移植到 iot_server 的備忘

- EKF 一次處理一筆，正好接在 `clothes/raw` ingest 後面。每個進行中的晾衣 session 存 `x[3]`、`P[3][3]`、`w0`、`t_last`（可以放 `drying_sessions` 的 JSONB 欄位）。
- 正式資料每分鐘一筆（10 次中位數），和這裡 `load_session(period="1min")` 的設定一樣。
- 掛上後前 5 分鐘不更新（還在晃）。session 開始的時間點就是使用者按下開始。
- 碰衣夾時會 10 秒一筆，而且讀值會亂跳：EKF 有 25σ 門檻擋掉，也可以先不處理 touch 觸發的那幾筆。
- EKF 的 ADS 偵測需要保留最近 15 筆 ADS 和歷史最低值；風的偵測需要韌體多傳一個欄位。
